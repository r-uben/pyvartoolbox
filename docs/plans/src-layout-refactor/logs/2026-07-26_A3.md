## The generated-file trap, avoided

`GRAPH.md` and `skill/handbook/INDEX.md` are **generated**, not source. Hand-editing
either would satisfy A3's grep gate and then fail (or silently drift from) the
regeneration comparison. The implementer changed the wording in the generator sources
and regenerated through the console scripts, which is the only correct route.

Verified by the dispatcher: `cp` the checked-in `GRAPH.md`, run
`uv run pyvartoolbox-graph-diagram`, diff → identical. The A3 reviewer went further
and cloned `ambropo/VAR-Toolbox` fresh, ran `uv run pyvartoolbox-convert-handbook`

including `INDEX.md`.

`skill/handbook/INDEX.md` was not named in the ticket. The implementer found it and

## Second malformed gate in this plan

A3's Done-when was written as
`grep -rl ... | xargs grep -Lc "repo checkout\|maintainer"`, expecting empty output.
`-c` overrides `-L` in GNU grep, so it prints counts unconditionally and **can never
pass**. Both the dispatcher and the reviewer independently confirmed this by running
it. `TICKETS.md` corrected to the working form (`grep -L`, no `-c`), which does
produce empty output.

That is the second unpassable gate found in this plan (after A1's stale "249 tests",
which should have been 252). Both share a cause: the gates were authored without being
executed. Worth carrying into how future plans are written — a Done-when that has
never been run is a guess, not a gate.
