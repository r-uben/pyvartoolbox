## Faithfulness of the regeneration check

The substance of the review, since failure-injection cannot prove it: does the test
reconstruct the generator's input the way the real generator does? A test that builds a
different page set could pass against a genuinely stale file — green while guarding
nothing.

Verified independently: `_index()` reads only `path.stem` and `path.name`, never file
contents (`_convert.py:31-32`). The real call site is `_index(written)` at
`_convert.py:272`, where `written` is the converted pages in enumeration order, before
`INDEX.md` itself is appended. Filenames are zero-padded (`{index:02d}`), and the
handbook currently holds 11 pages (`01-…` through `11-…`), so sorted order and
enumeration order coincide. The test's `sorted(...)` reconstruction is therefore
faithful.

Known limit, not worth code today: at ≥100 sections `"100-"` sorts before `"11-"` and
the two orders would diverge. That needs 89 more sections against a fixed upstream
handbook.
