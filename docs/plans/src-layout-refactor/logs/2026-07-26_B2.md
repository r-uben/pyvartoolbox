# TICKET-B2 — State the point-versus-set rule and stop `impact_matrix` lying

Date: 2026-07-26 · Branch: `feat/10-src-layout-refactor` · Status: DONE (verified + corrected, uncommitted at time of writing)

## What shipped

The point-identified-vs-set-identified rule is now documented at the top of both
`ident.py` and `sign.py`, and recorded in `skill/references/api.md`. The old
`_PLANNED` dict split into `_SET_IDENTIFIED` (implemented in `sign.py`, unreachable
through `impact_matrix` by construction) and `_PLANNED` (genuinely unwritten — only
`exog` remains). `impact_matrix` now raises, for a set-identified name:

> identification scheme 'sign' (sign restrictions) is set-identified: it admits a
> family of admissible impact matrices rather than a single one, so there is no B for
> impact_matrix to return. The scheme itself is implemented — call
> sign_restricted_irf(model, restrictions, ...), which samples the identified set and
> returns a distribution of impulse responses. impact_matrix covers the
> point-identified schemes only: ('chol', 'longrun', 'iv')

Files: `src/pyvartoolbox/ident.py`, `src/pyvartoolbox/sign.py`,

## Defect found and corrected during verification

The as-implemented module docstrings overclaimed a numerical invariant. `ident.py`
stated flatly that `iv` "deliberately does not" satisfy `sigma == B0inv @ B0inv.T`,
and `sign.py` made the parallel claim for the sign+IV path. **Both are conditional,
not absolute.** Measured on a 200×3 VAR, `nlags=2`:

| instrument sample | `max|B B^T - sigma|` |
|---|---|
| spans the full VAR sample | `5.551e-16` (holds to machine precision) |
| observed on a shorter subsample | `9.537e-02` (breaks materially) |

The mechanism is in `_complete`: it normalises `q1 = P^-1 b1` before completing, so
the identity survives exactly when `||q1||` is already 1 — which is the case precisely
when the IV sample coincides with the VAR sample. `_complete`'s own function docstring
was correctly hedged ("only approximately unit-norm"); the *new module-level* prose
dropped the hedge.

Both docstrings were corrected to state the condition. `skill/references/api.md`
makes no numerical-identity claim, so it needed no change. Gates re-run after the fix:
all still pass.

This is the failure mode the ticket exists to prevent — wrong prose about a numerical
invariant is worse than no prose — reappearing inside the fix itself. Tests could not
have caught it: every claim was in a docstring, and the suite was green throughout.
