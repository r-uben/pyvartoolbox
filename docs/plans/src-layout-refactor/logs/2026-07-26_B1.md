## Critical invariant — held

The intentional asymmetry survives the extraction. `ident._complete`
(`ident.py:101`) still restores the identified column after completion
(`B[:, 0] = b1`), deliberately breaking `B @ B.T == sigma`; the plain non-IV
rotation path in `sign.py` still does not. Independently confirmed by the
dispatcher, not just the reviewer. The Cholesky positive-definite error string is
character-identical to `a5710ec` (diffed).

`orthonormal_completion` is one routine, not a flag-switched two-in-one — signature
is `(q1, nvar)` with no behaviour selector, so the two call sites have nothing to
drift apart on.

## Note carried forward (not a defect)

`sign.py:157` (`B[:, 0] = b_iv`, the **sign+IV combined** path) also overwrites
column 0 after completion, which superficially resembles the `ident` pattern. It is
**pre-existing and untouched** by this ticket — present at `a5710ec`, absent from
B1's diff (both verified independently). Recorded because the "sign never restores a
column" invariant is scoped to the *non-IV rotation path*, not to `sign.py` globally;
a future audit that states it too broadly will flag a false positive here.
